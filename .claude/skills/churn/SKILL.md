---
name: churn
description: Add a churn breakdown (code / tests / comments & docs / generated) to a pull request description. Use when opening or updating a PR and the diff is large enough that reviewers benefit from knowing what it is made of.
argument-hint: PR number or URL (default - the current branch's PR)
---

## Instructions

1. Make sure `churn` and `cloc` are installed (`which churn cloc`). If not: `brew install cloc` and `uv tool install git+ssh://git@github.com/launchdarkly-labs/churn.git`.
2. Run churn on a throwaway blobless clone, so no local checkout of the PR is needed. Given a PR number or URL (`<owner>/<repo>` and `<n>` come from it; get `<base>` from `gh pr view <n> -R <owner>/<repo> --json baseRefName -q .baseRefName`):

   ```sh
   d=$(mktemp -d) && gh repo clone <owner>/<repo> "$d" -- --filter=blob:none --no-checkout
   cd "$d" && git fetch origin pull/<n>/head && churn origin/<base> FETCH_HEAD
   ```

   With no PR given, use the current branch's PR and run plain `churn` in the repo (diffs `HEAD` against the merge base with `origin/main`; commit first, since uncommitted changes are not counted).
3. Append the output at the bottom of the PR description, after a blank line, unless the user says where to put it. Do not edit it.
4. To update an existing PR, fetch the current body (`gh pr view <n> --json body -q .body`), replace the previous churn block (everything from its first `$\color` line through the `generated by churn` footer) or append if there is none, and write it back with `gh pr edit <n> --body-file <file>`.
5. For places that don't render HTML or math (terminal, Slack, commit messages), use `churn -f text` instead.

## Notes

- If a repo buckets files wrongly, add a `.churn.toml` at its root (see README) and re-run; use `churn --files` to see each file's bucket.
- Keep PR descriptions short; the churn block counts toward any length limit.
